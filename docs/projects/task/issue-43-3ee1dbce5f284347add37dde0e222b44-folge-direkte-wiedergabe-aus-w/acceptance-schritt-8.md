## Abweichungen

- [ ] `SeasonIdsEqual` vergleicht nur die Staffel-Ids (`MediaDetailsPage.xaml.cs` Z. 278–279), `SeasonItem` ist aber ein Record mit `Episodes`-Listenmember — Wertgleichheit scheitert an der neuen Listenreferenz. Wird `details.Seasons` mit identischen Ids, aber neuen Instanzen neu gebaut — konkret `MarkEpisodeWatchedInDetails` (`AppUpdate.cs` Z. 3940–3955, Rückkehr von der Wiedergabe einer markierten Episode) und der Reload beim Zurücknavigieren von der Episoden-Detailseite (`OnAppearing` Z. 99–108 → `identityMatches == false` → erneute `MediaDetailsRequestedMessage` → `MapShow`/`MapSeasons` erzeugt neue `SeasonItem`-Instanzen, `MediaDetailsService.cs` Z. 606 ff.) — bleibt `SeasonPicker.ItemsSource` auf den alten Instanzen (Z. 248–252 greift nicht), anschließend setzt Z. 254–257 `SelectedItem` auf eine `SeasonItem`-Instanz, die nicht in der `ItemsSource` liegt. MAUI-`Picker` löst `SelectedIndex` per `IndexOf` auf → −1 → die Staffelbox verliert ihre sichtbare Auswahl (zeigt den Titel „Staffel"), obwohl das Modell `SelectedSeasonId` weiter führt — und jede spätere Benutzerwahl wird beim nächsten Model-Tick erneut optisch verworfen (Dispatch bleibt korrekt). Vor der Änderung war das unproblematisch, weil `ItemsSource`/`SelectedItem` jeden Tick auf zueinander passende Instanzen neu gesetzt wurden. Die Episodenliste selbst aktualisiert korrekt (`ReferenceEquals`-Guard Z. 262–266 reagiert auf neue `Episodes`-Listen). Windows-sichtbarer Anzeige-Desync in diesen Flüssen — kein Zurückspringen im Modell, kein Fehl-Dispatch, aber `SelectedItem` ist dann nicht mehr synchron zum Modell. Umfasst auch: Serverseitig umbenannte Staffeln bei gleichen Ids behalten den alten Anzeigenamen (Cache wird nur über die Id-Sequenz invalidiert).
