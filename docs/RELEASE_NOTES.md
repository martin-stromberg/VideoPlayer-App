# Release Notes

## Important Notes Before Update

- There are no special notices.

## What's New

- Repeated playback without crash (`VideoPlayer.Maui`): starting another video after a finished or closed playback no longer crashes the app with an unhandled COM exception — the playback page now releases its model subscription when closed and all native player access runs on the UI thread; progress reporting and the "watched" marking work unchanged.
- Player controls usable in full view (`VideoPlayer.Maui`): on the playback page the native transport controls (play/pause, seek, etc.) were unreachable because the app's header overlay invisibly covered the whole video area; the overlay now only occupies its visible top band and the title area passes input through, while the "Mini player" button stays usable.
- Web-style dark design (`VideoPlayer.Maui`): the new app now uses the web application's documented design tokens — deep black backgrounds, graded dark surfaces, the red primary color with hover state, pill-shaped chips/badges/round icon buttons and 4px button corners. All colors come from central `Vp*` style resources; behavior is unchanged.
- New platform-neutral server API client (`VideoPlayer.ApiClient`): login, health check, sources, recently added items, continue watching (progress/hide/skip), favorites, media lookup and picture retrieval.
- Fixed retry strategy for failed server responses (retries with 1 s/2 s/4 s delays) and one-time token renewal on “unauthorized”.
- Client gate via `X-API-Key` header, configurable through environment variable `VIDEOWEBPLAYER_MAUI_API_TOKEN`, build property `VideoPlayerApiToken` or client options.
- New app foundation (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): startup with a loading screen and server reachability check, side menu navigation (Home, Sources, Favorites, Downloads, Profile, Settings) and placeholder pages. The new app uses its own lightweight MVU cycle and runs alongside the existing app, which remains unchanged.
- New settings management (`VideoPlayer.Storage`): the Settings page now offers automatic downloads, number of episodes to preload, Wi-Fi-only downloads, a download quota in gigabytes (default 5 GB), automatic deletion of watched episodes, auto-resume and the watched time window. All values persist across app restarts and are validated against their allowed ranges.
- Structured local storage with backup separation: backup-relevant data (server list, last connected server, profile data, settings, unsynchronized progress) is kept apart from rebuildable data (offline videos, thumbnails, cached lists, download manifest). On iOS the non-backup locations are excluded via the platform backup attribute, on Windows backup-relevant data goes to the roaming profile directory. Secrets (passwords, tokens) are stored exclusively in platform secure storage and never enter backups; separate profiles via `VIDEOPLAYER_PROFILE` are fully isolated.
- Server management with first-run setup (`VideoPlayer.Storage` + `VideoPlayer.Maui`): on first launch without a configured server a setup dialog offers manual address entry and automatic network discovery (mDNS `_http._tcp.local.` plus UDP broadcast on port 5001). Only servers that pass a live connection check are saved; afterwards the app starts directly with the last connected server. A discreet “Switch server” entry in Settings lists known servers, allows adding new ones and switches the active server without touching any other setting.
- Connection workflow and sign-in (`VideoPlayer.Mvu` + `VideoPlayer.Maui`): on launch the app automatically connects to the last used server and signs in with securely stored credentials, landing in one of four states — connected, sign-in required, server setup required, or offline (when the server is unreachable but local offline data exists). A new sign-in page asks only for username and password (username prefilled), shows inline errors and offers a way back to server selection. Expired tokens are renewed silently via a stored-credentials re-login; only missing or rejected credentials bring up the sign-in page. After a backup restore the app reconnects to the last used server automatically and asks for the password only because secrets are intentionally excluded from backups.
- Network status detection and synchronization: the app detects online/offline transitions at runtime, shows the offline banner without interrupting the current page, and automatically reconnects after network recovery (health check, silent sign-in). A SignalR real-time connection to the server hub `hubs/mediaupdate` refreshes continue-watching, favorites and newly scanned content without manual refresh; if the connection drops permanently it is re-established while online. Playback progress that cannot be delivered is kept in a persistent, backup-covered queue (`pending_progress`) and replayed in chronological order during synchronization — latest position per media, deleted only after successful delivery — surviving app restarts and backup restores.
- Home page with cached media lists (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): the new home page shows three horizontal lists — Continue watching, Favorites and Recently added — as poster cards in the style of the existing app. Lists are loaded from the local cache first, so reopening the app shows content immediately (also offline), and they refresh automatically once fresh server data arrives or a server event (progress, favorites, newly scanned content) updates the corresponding cache. Poster images are loaded via `api/pictures/{id}` and stored in the non-backup preview storage. Tapping an item opens the detail page via the `mediadetails` route carrying the media identity.
- Source browsing and media detail pages: the Sources menu lists the media sources authorized on the server (with icons, a clear offline notice when no connection exists, and retry on failure). Selecting a source opens a browsing page with a horizontal genre bar (including “All”), text search and a poster grid with incremental loading. Detail pages cover movies and episodes (basic details), movie collections (contained movies) and TV shows (season picker with episode lists); episodes and seasons resolve to the show context via embedded references. A favorite star toggles the mark server-side (`api/favorites/toggle`), refreshes the local `cached_favorites` copy authoritatively and updates the home-page favorites list automatically — no silent toggling, consistent after app restart.
- Favorites and Profile pages: the Favorites menu page lists the signed-in server user's favorites as poster cards with title and media type in the style of the web app. Online the server is authoritative — the local `cached_favorites` copy is synchronized first, then displayed; a per-row "Remove" action deletes the favorite server-side (`api/favorites/remove` with the favorite-entry id), refreshes the copy and the home-page favorites list automatically. Offline the cached list stays visible with a clear notice and removal disabled. Tapping a card opens the media detail page with the show/season/episode context. The Profile page shows the signed-in user (username and, when present in the token, e-mail), the active local profile (`VIDEOPLAYER_PROFILE`) and the connected server address; "Sign out" ends the session locally without a server endpoint — tokens and credentials are cleared and the app returns to the sign-in page while server list, settings and offline data are kept.
- Video playback with Picture-in-Picture and progress tracking (`VideoPlayer.Maui` + `VideoPlayer.Mvu` + `CommunityToolkit.Maui.MediaElement` 10.0.0): a dedicated player page (route `player`) plays server streams (`api/items/{type}/{id}/stream` with the access token) or completed downloads from the local manifest — the source abstraction is ready for the upcoming download feature. Playback resumes at the continue-watching position (server list, or the cached copy when offline). Progress is reported every five seconds while playing, marked "watched" within the configured end window and queued losslessly in `pending_progress` when offline for automatic replay after reconnect. With auto-resume enabled the next episode starts automatically near the end (across seasons, in episode order) — never while paused. Source or playback failures show a clear message and fall back to the next episode when available. On Windows a "Mini player" button switches the app window into a compact always-on-top overlay; on iOS the native transport controls provide Picture-in-Picture (background audio is declared in `Info.plist`). Play buttons appear on the detail page for movies and episodes and on each entry of the episode list.
- Download management and automatic downloads (`VideoPlayer.Mvu` + `VideoPlayer.Maui`): media can be downloaded for offline use via a "Download" action on the detail page (movie header and per episode). The "Downloads" menu page lists every job with title, type, state, progress bar and readable errors — usable offline since the inventory lives in the local manifest (`download_manifest`, excluded from backup) — with per-item Cancel, Retry and Delete actions plus the quota usage line. Up to two downloads run in parallel; interrupted jobs restart automatically on connect, after app restart and on network/Wi-Fi recovery (no range resume — the server stream restarts from the beginning). The configured storage quota (default 5 GB) is enforced before and during transfers, including across parallel transfers. "Wi-Fi-only downloads" holds jobs until an unmetered fixed-network connection is present (Wi-Fi or Ethernet). With automatic downloads enabled the app preloads the next episodes of continue-watching entries (count from settings, across seasons via the show context; movie entries download the movie itself), throttled after synchronization, list changes and enabling the setting; completed downloads of watched episodes are optionally removed automatically. Playback prefers the local file and falls back to the server stream when it is missing.
- Full offline operation and backup-restore recovery (`VideoPlayer.Mvu` + `VideoPlayer.Maui` + `VideoPlayer.Storage`): without a server connection the home page keeps working — Continue Watching is built exclusively from completed downloads whose files still exist, missing next episodes appear as dimmed placeholder cards labeled “Not downloaded”, and Favorites/Recently added show the last cached state. Downloads play from the local file; detail pages render offline snapshots that disable server-only actions (favorite toggle, downloads, sources, profile retrieval). After a cloud-backup restore the app reuses the last known server and a stored token or credentials when available; missing secrets lead to a clear re-sign-in notice on the sign-in page with the username prefilled. If the known server is unreachable the app enters offline mode when local data exists, otherwise server setup. On reconnection a full synchronization uploads pending progress and refreshes the home lists. Corrupt cache entries are discarded and re-synchronized; corrupt database files are quarantined as `*.corrupt-*` and rebuilt, with a banner informing the user.
- Dynamic source entries in the side menu (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): while connected, the side menu shows a "Sources" section header with a dedicated entry per authorized source — name and source icon — that opens the source's title overview directly; the former "Sources" overview page is removed. A status line appears while the list loads, an empty result is marked with a notice, and a failed load shows a visible error entry with a retry option. Without a server connection no source entries are shown.
- Downloads page without flicker (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): the downloads list no longer rebuilds on every progress tick — a stable observable list of per-item view models is reconciled in place, so a running or queued download updates only its own progress bar while the rest of the page stays untouched. Loading, enqueueing, cancelling, deleting, resuming and automatic downloads are unchanged.

## Neuerungen

- Wiederholte Wiedergabe ohne Absturz (`VideoPlayer.Maui`): Der Start eines weiteren Videos nach beendeter oder geschlossener Wiedergabe führt nicht mehr zum Abbruch der App mit einer unbehandelten COM-Ausnahme — die Wiedergabeseite meldet ihr Modell-Abo beim Schließen ab und alle Zugriffe auf das native Player-Element laufen auf dem UI-Thread; Fortschrittsmeldung und „Angesehen"-Markierung funktionieren unverändert.
- Player-Steuerung in der Vollansicht bedienbar (`VideoPlayer.Maui`): Auf der Wiedergabeseite waren die nativen Transportsteuerungen (Play/Pause, Seek u. a.) nicht erreichbar, weil die Kopf-Überlagerung der App unsichtbar die gesamte Videofläche abdeckte; die Überlagerung belegt jetzt nur noch ihr sichtbares Kopfband und die Titelfläche lässt Eingaben durch, während der „Mini-Player"-Schalter nutzbar bleibt.
- Dunkles Web-Design (`VideoPlayer.Maui`): Die neue App nutzt die dokumentierten Design-Tokens der Webanwendung — tiefschwarze Hintergründe, abgestufte dunkle Flächen, rote Primärfarbe mit Hover-Zustand, pill-förmige Chips/Badges/runde Symbol-Schaltflächen und 4px-Button-Ecken. Alle Farben kommen aus zentralen `Vp*`-Stilressourcen; die Bedienung ist unverändert.
- Neuer plattformneutraler Server-API-Client (`VideoPlayer.ApiClient`): Anmeldung, Erreichbarkeitsprüfung, Quellen, „Neu im Programm", Weiterschauen (Fortschritt/Ausblenden/Überspringen), Favoriten, Mediennachschlagen und Bildabrufe.
- Feste Wiederholungsstrategie bei fehlerhaften Serverantworten (Wiederholungen nach 1 s/2 s/4 s) und einmalige Token-Erneuerung bei „nicht autorisiert".
- Client-Gate per `X-API-Key`-Header, konfigurierbar über die Umgebungsvariable `VIDEOWEBPLAYER_MAUI_API_TOKEN`, die Build-Eigenschaft `VideoPlayerApiToken` oder die Client-Optionen.
- Neues App-Grundgerüst (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): Startvorgang mit Ladeanzeige und Erreichbarkeitsprüfung des Servers, Seitenmenü-Navigation (Startseite, Quellen, Favoriten, Downloads, Profil, Einstellungen) und Platzhalterseiten. Die neue App nutzt einen eigenen schlanken MVU-Kreislauf und läuft parallel zur bisherigen App, die unverändert bestehen bleibt.
- Neue Einstellungsverwaltung (`VideoPlayer.Storage`): Die Seite „Einstellungen" bietet nun automatische Downloads, Anzahl vorzuladender Episoden, Downloads nur im WLAN, ein Speicherplatzkontingent in Gigabyte (Standard 5 GB), automatisches Löschen gesehener Episoden, Auto-Fortsetzung und das „Als angesehen"-Zeitfenster. Alle Werte bleiben über App-Neustarts erhalten und werden auf ihre zulässigen Bereiche geprüft.
- Strukturierte lokale Datenhaltung mit Backup-Trennung: Backup-pflichtige Daten (Serverliste, zuletzt verbundener Server, Profildaten, Einstellungen, unsynchronisierte Fortschritte) sind von neu aufbaubaren Daten (Offline-Videos, Vorschaubilder, zwischengespeicherte Listen, Download-Manifest) getrennt. Unter iOS werden die nicht zu sichernden Ablageorte über das Plattform-Backup-Attribut ausgeschlossen, unter Windows landen backup-pflichtige Daten im Roaming-Profilverzeichnis. Geheimnisse (Passwörter, Token) liegen ausschließlich in der sicheren Plattformablage und gelangen nie ins Backup; getrennte Profile über `VIDEOPLAYER_PROFILE` sind vollständig isoliert.
- Serververwaltung mit Erststart-Einrichtung (`VideoPlayer.Storage` + `VideoPlayer.Maui`): Beim ersten Start ohne hinterlegten Server bietet ein Einrichtungsdialog die manuelle Adresseingabe und die automatische Netzwerk-Erkennung (mDNS `_http._tcp.local.` sowie UDP-Broadcast auf Port 5001). Gespeichert wird nur, wer eine echte Verbindungsprüfung besteht; danach startet die App direkt mit dem zuletzt verbundenen Server. Ein dezenter Eintrag „Server wechseln" in den Einstellungen listet bekannte Server, erlaubt das Hinzufügen und wechselt den aktiven Server, ohne die übrigen Einstellungen zu verändern.
- Verbindungs-Workflow und Anmeldung (`VideoPlayer.Mvu` + `VideoPlayer.Maui`): Die App verbindet sich beim Start automatisch mit dem zuletzt genutzten Server und meldet sich mit den sicher gespeicherten Zugangsdaten an — Ergebnis ist einer von vier Zuständen: verbunden, Anmeldung erforderlich, Servereinrichtung erforderlich oder offline (bei nicht erreichbarem Server mit vorhandenen lokalen Daten). Eine neue Anmeldemaske fragt nur Benutzername und Passwort ab (Benutzername vorbefüllt), zeigt Inline-Fehler und bietet den Weg zurück zur Serverauswahl. Abgelaufene Anmelde-Tokens werden im Hintergrund über eine erneute Anmeldung mit den gespeicherten Zugangsdaten erneuert; nur fehlende oder abgelehnte Zugangsdaten führen zur Anmeldemaske. Nach einer Backup-Wiederherstellung verbindet sich die App automatisch mit dem letzten Server — die erneute Passwortabfrage erfolgt nur, weil Geheimnisse bewusst nicht ins Backup gelangen.
- Netzwerkstatus-Erkennung und Synchronisation: Die App erkennt Online↔Offline-Wechsel zur Laufzeit, zeigt den Offline-Hinweis ohne die aktuelle Seite zu verlassen und stellt die Verbindung nach Netzwerk-Wiederkehr automatisch wieder her (Erreichbarkeitsprüfung, stille Anmeldung). Eine SignalR-Echtzeit-Verbindung zum Server-Hub `hubs/mediaupdate` aktualisiert Weiterschauen, Favoriten und neu eingescannte Inhalte ohne manuelle Aktualisierung; bei endgültigem Verbindungsverlust wird sie im Online-Zustand neu aufgebaut. Nicht zustellbare Wiedergabefortschritte landen in einer persistenten, backup-pflichtigen Warteschlange (`pending_progress`) und werden bei der Synchronisation in chronologischer Reihenfolge nachgesendet — je Medium nur der neueste Stand, gelöscht erst nach erfolgreicher Übertragung — und überstehen App-Neustarts und Backup-Wiederherstellungen.
- Startseite mit gecachten Medienlisten (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): Die neue Startseite zeigt drei horizontale Listen — „Weiterschauen", „Favoriten" und „Neu im Programm" — als Poster-Karten im Stil der bisherigen App. Die Listen werden zuerst aus dem lokalen Cache geladen, sodass beim erneuten Öffnen sofort Inhalte sichtbar sind (auch offline); sobald aktuelle Serverdaten vorliegen oder ein Server-Ereignis (Fortschritt, Favoriten, neu eingescannte Inhalte) den zugehörigen Cache aktualisiert, frischen sich die Listen automatisch auf. Vorschaubilder kommen über `api/pictures/{id}` und liegen in der nicht backup-pflichtigen Vorschau-Ablage. Das Antippen eines Eintrags öffnet über die Route `mediadetails` die Detailseite des Mediums.
- Quellen-Browsing und Medien-Detailseiten: Die Menüseite „Quellen" listet die vom Server freigegebenen Medienbereiche (mit Icons, klarem Offline-Hinweis ohne Verbindung und „Erneut laden" bei Fehlern). Die Auswahl öffnet eine Browsing-Seite mit horizontaler Genre-Leiste (inklusive „Alle"), Textsuche und Poster-Raster mit seitenweisem Nachladen. Detailseiten decken Filme und Episoden (Basisdetails), Filmkollektionen (enthaltene Filme) und Serien (Staffel-Auswahl mit Episodenlisten) ab; Episoden und Staffeln lösen über eingebettete Bezüge zum Serienkontext auf. Ein Favoriten-Stern schaltet die Markierung serverseitig um (`api/favorites/toggle`), erneuert die lokale Kopie `cached_favorites` autoritativ und aktualisiert die Startseiten-Favoriten automatisch — kein stilles Umschalten, konsistent nach App-Neustart.
- Favoriten- und Profil-Seite: Die Menüseite „Favoriten" zeigt die Favoriten des am Server angemeldeten Benutzers als Poster-Karten mit Titel und Medientyp im Stil der Webanwendung. Online bleibt der Server führend — die lokale Kopie `cached_favorites` wird zuerst synchronisiert und dann angezeigt; die Aktion „Entfernen" je Eintrag löscht den Favoriten serverseitig (`api/favorites/remove` mit der Favoriten-Eintrags-ID), erneuert die Kopie und die Startseiten-Favoriten folgen automatisch. Offline bleibt die gespeicherte Liste mit klarem Hinweis sichtbar und das Entfernen ist gesperrt. Ein Tap auf eine Karte öffnet die Detailseite des Mediums mit dem Serienkontext (Staffel/Episode). Die Profil-Seite zeigt den angemeldeten Benutzer (Benutzername und, soweit im Token enthalten, E-Mail), das aktive lokale Profil (`VIDEOPLAYER_PROFILE`) und die Serveradresse; „Abmelden" beendet die Sitzung lokal ohne Server-Endpunkt — Token und Zugangsdaten werden gelöscht und die App kehrt zur Anmeldemaske zurück, während Serverliste, Einstellungen und Offline-Daten erhalten bleiben.
- Videowiedergabe mit Picture-in-Picture und Fortschrittsverfolgung (`VideoPlayer.Maui` + `VideoPlayer.Mvu` + `CommunityToolkit.Maui.MediaElement` 10.0.0): Eine eigene Wiedergabeseite (Route `player`) spielt Server-Streams (`api/items/{typ}/{id}/stream` mit Zugriffstoken) oder fertige Downloads aus dem lokalen Manifest ab — die Quellenabstraktion ist für den kommenden Download-Ausbau vorbereitet. Die Wiedergabe setzt am gemerkten Weiterschauen-Stand fort (Serverliste, offline aus der Cache-Kopie). Der Fortschritt wird im Fünf-Sekunden-Takt gemeldet, innerhalb des eingestellten Endfensters als „angesehen" markiert und offline verlustfrei in `pending_progress` vorgehalten — bei Online-Rückkehr wird automatisch nachgesendet. Bei aktivierter Auto-Fortsetzung startet gegen Ende automatisch die nächste Episode (staffelübergreifend, in Episodenreihenfolge) — nie im Pausenzustand. Quell- oder Abspielfehler zeigen eine verständliche Meldung und fallen auf die nächste Episode zurück, sofern vorhanden. Unter Windows schaltet ein „Mini-Player"-Schalter das App-Fenster in ein kompaktes, immer vordergrundiges Overlay; unter iOS stellt die native Transportsteuerung Picture-in-Picture bereit (Hintergrund-Audio ist in der `Info.plist` deklariert). „Abspielen"-Schaltflächen stehen auf der Detailseite für Filme und Episoden sowie an jedem Eintrag der Episodenliste.
- Downloads-Seite ohne Flackern (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): Die Downloads-Liste wird bei jedem Fortschritts-Tick nicht mehr komplett neu aufgebaut — eine stabile, beobachtbare Liste aus Eintrags-ViewModels wird in-place abgeglichen, sodass sich bei laufendem oder geplantem Download nur der Fortschrittsbalken des betroffenen Eintrags verändert und die übrige Anzeige unberührt bleibt. Laden, Einreihen, Abbrechen, Löschen, Fortsetzen und automatische Downloads bleiben unverändert.
- Download-Verwaltung und automatische Downloads (`VideoPlayer.Mvu` + `VideoPlayer.Maui`): Medien lassen sich über „Herunterladen" auf der Detailseite (Film-Kopfbereich und je Episode) für die Offline-Nutzung laden. Die Menüseite „Downloads" zeigt alle Aufträge mit Titel, Typ, Zustand, Fortschrittsbalken und verständlichen Fehlern — offline nutzbar, da der Bestand im lokalen Manifest (`download_manifest`, außerhalb des Backups) liegt — samt den Aktionen Abbrechen, Erneut versuchen und Löschen sowie der Kontingent-Belegung. Bis zu zwei Downloads laufen parallel; unterbrochene Aufträge werden beim Verbindungsaufbau, nach App-Neustart und bei Netzwerk-/WLAN-Rückkehr automatisch neu gestartet (kein Range-Resume, der Server-Stream beginnt erneut). Das konfigurierte Speicherplatzkontingent (Standard 5 GB) wird vor und während der Übertragung durchgesetzt — auch über parallele Transfers hinweg. „Downloads nur im WLAN" hält Aufträge bis zu einer ungedrosselten Festnetz-Verbindung zurück (WLAN oder Ethernet). Bei aktivierten automatischen Downloads lädt die App die nächsten Episoden der Weiterschauen-Einträge vor (Anzahl aus der Einstellung, staffelübergreifend im Serienkontext; Film-Einträge laden den Film selbst), gedrosselt nach Synchronisation, Listen-Änderung und Einschalten der Einstellung; optional werden Downloads gesehener Episoden automatisch entfernt. Die Wiedergabe bevorzugt die lokale Datei und fällt bei fehlender Datei auf den Server-Stream zurück.
- Vollständiger Offlinebetrieb und Wiederherstellung nach Backup (`VideoPlayer.Mvu` + `VideoPlayer.Maui` + `VideoPlayer.Storage`): Ohne Serververbindung bleibt die Startseite nutzbar — „Weiterschauen" wird ausschließlich aus abgeschlossenen Downloads mit vorhandener Datei gebildet, fehlende Folge-Episoden erscheinen als abgedunkelte Platzhalter-Karten mit dem Hinweis „Nicht heruntergeladen", Favoriten und „Neu im Programm" zeigen den letzten Cache-Stand. Downloads spielen aus der lokalen Datei; Detailseiten entstehen als Offline-Snapshots, die serverseitige Aktionen (Favorit, Download, Quellen, Profilabruf) unterbinden. Nach einer Cloud-Backup-Wiederherstellung nutzt die App den zuletzt verbundenen Server sowie gespeichertes Token oder Zugangsdaten; fehlende Geheimnisse führen zu einem verständlichen Wiederanmelde-Hinweis auf der Anmeldemaske mit vorbefülltem Benutzernamen. Ist der bekannte Server nicht erreichbar, wechselt die App bei lokalem Datenbestand in den Offline-Modus, sonst in die Server-Einrichtung. Bei Wiederverbindung läuft eine Voll-Synchronisation, die ausstehende Fortschritte nachsendet und die Startseiten-Listen aktualisiert. Beschädigte Cache-Einträge werden verworfen und neu synchronisiert; beschädigte Datenbankdateien werden als `*.corrupt-*` beiseitegelegt und neu aufgebaut — ein Hinweisbanner informiert den Nutzer.
- Dynamische Quellen-Einträge im Seitenmenü (`VideoPlayer.Maui` + `VideoPlayer.Mvu`): Im verbundenen Zustand zeigt das Seitenmenü unter der Sektionsüberschrift „Quellen" je freigegebener Quelle einen eigenen Eintrag mit Name und Quellen-Icon, der direkt in die Titelübersicht der Quelle führt — die bisherige Übersichtsseite „Quellen" entfällt. Während des Ladens erscheint eine Statuszeile, ein leerer Stand wird mit einem Hinweis gekennzeichnet und bei einem Ladefehler zeigt ein sichtbarer Fehlereintrag die Meldung samt Neuversuch. Ohne Serververbindung werden keine Quellen-Einträge angezeigt.
