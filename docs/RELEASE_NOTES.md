# Release Notes

## Important Notes Before Update

- Scheduled review workflows activate on reaching `main` (`.github/workflows`, issue #95): the three recurring review workflows run their schedules only once they exist on the default branch — after this release is promoted to `main` they will start filing review issues automatically (monthly architecture/security review, weekly NuGet check, yearly compliance review; each also runnable manually via `workflow_dispatch` at any time).
- Signed tvOS release path stays disabled until activated (`package-tvos`, issue #86): the `package-tvos` job in the release workflows only runs when the repository variable `TVOS_SIGNING_ENABLED=true` is set and the `TVOS_*` secrets (distribution certificate `.p12`, provisioning profile, App Store Connect API key) are configured — the tvOS app record, provisioning profile and certificate must first be created in the Apple Developer account / App Store Connect. Without them the job is skipped and the release pipelines stay green (no tvOS store package is produced). See the [tvOS deployment help](help/tv-app/deployment.md).

## What's New

- Recurring review automation (`.github/workflows`, issue #95): three scheduled GitHub Actions workflows now file review issues in the repository tracker and mention `@softwarewerkstatt` to trigger external handling — a monthly architecture and security review (1st of month, 05:00 UTC), a weekly NuGet package check (Mondays, 05:00 UTC) and a yearly compliance/copyright review (January 1st, 05:00 UTC); each can also be run manually via `workflow_dispatch`. Every run ensures its dedicated review label (`review-architektur-sicherheit`, `review-nuget`, `review-compliance`), skips creation when an open issue of the same type already exists, and otherwise creates an issue titled with the current period whose body comes from `.github/issue-bodies/` (first line `@softwarewerkstatt`). The schedules only take effect once the workflows reach the default branch. See the [review automation help](help/review-automatisierung.md).
- Apple TV app (tvOS) — Lean-back player via .NET for tvOS (`VideoPlayer.TvOS`, issue #86): a new standalone tvOS app brings the media library to the television, fully operable via Siri Remote and the tvOS focus engine, built on the same platform-neutral MVU core as the main app. Server setup is remote-friendly: automatic server discovery in the local network (mDNS + UDP), a list of known servers with switching, manual address entry, device pairing via one-time code or ticket/short code, sign-in with username/password and automatic re-login from the keychain. The home page stacks focusable horizontal carousels — Continue Watching with progress bars, Favorites, Recently added, the server's seasonal genre sections and a Sources row — with cache-first loading, server events and poster caching. Source browsing offers search, genre filtering and a paged poster grid; detail pages cover all media types with Play, Download and Favorite actions. Playback runs in the native tvOS fullscreen player with progress tracking, resume position, auto-advance (series and playlist context) and system track selection. Playlists are available read-only (grouped overview, paged entry grid, playback from any entry); manual downloads run suspension-safe over a background `NSUrlSession` with expiry date, storage quota, reconcile pass and a downloads page with per-entry actions; a slim settings page exposes download retention/quota, auto-resume and the watched end window plus account/server sections. Not offered on tvOS: auto-download preload, delete-after-playback, playlist management and log shipping. Delivery includes the App-Store asset catalog, a signed release path (reusable `package-tvos` action wired into both merge workflows) and the `scripts/tvOS-Deployment.ps1` helper for Mac-delegated builds — gated behind `TVOS_SIGNING_ENABLED` (see Important Notes). See the [tvOS app help](help/tv-app/index.md).

## Wichtige Hinweise vor dem Update

- Zeitgesteuerte Review-Workflows werden erst mit Erreichen von `main` aktiv (`.github/workflows`, Issue #95): Die drei wiederkehrenden Review-Workflows führen ihre Zeitpläne nur aus, sobald sie auf dem Default-Branch liegen — nach der Promotion dieses Releases auf `main` beginnen sie automatisch, Review-Issues anzulegen (monatlicher Architektur-/Sicherheits-Review, wöchentlicher NuGet-Check, jährlicher Compliance-Review; jederzeit zusätzlich manuell per `workflow_dispatch` startbar).
- Signierter tvOS-Release-Pfad bleibt bis zur Aktivierung deaktiviert (`package-tvos`, Issue #86): Der `package-tvos`-Job in den Release-Workflows läuft nur, wenn die Repository-Variable `TVOS_SIGNING_ENABLED=true` gesetzt und die `TVOS_*`-Secrets (Distribution-Zertifikat `.p12`, Provisioning-Profil, App-Store-Connect-API-Key) hinterlegt sind — App-Record, Provisioning-Profil und Zertifikat müssen vorher im Apple-Developer-Account / App Store Connect angelegt werden. Ohne diese Vorbedingungen wird der Job übersprungen, die Release-Pipelines bleiben grün (es entsteht kein tvOS-Store-Paket). Siehe die [tvOS-Deployment-Hilfe](help/tv-app/deployment.md).

## Neuerungen

- Wiederkehrende Review-Automatisierung (`.github/workflows`, Issue #95): Drei zeitgesteuerte GitHub-Actions-Workflows legen jetzt Review-Issues im Repository-Tracker an und erwähnen `@softwarewerkstatt` zur Auslösung der externen Bearbeitung — ein monatlicher Architektur- und Sicherheits-Review (jeweils am 1., 05:00 UTC), ein wöchentlicher NuGet-Paket-Check (montags, 05:00 UTC) und ein jährlicher Compliance-/Copyright-Review (1. Januar, 05:00 UTC); jeder Workflow ist zusätzlich manuell per `workflow_dispatch` startbar. Jeder Lauf stellt sein Review-Label sicher (`review-architektur-sicherheit`, `review-nuget`, `review-compliance`), überspringt die Anlage, wenn bereits ein offenes Issue desselben Typs existiert, und erzeugt sonst ein Issue mit dem aktuellen Zeitraum im Titel und dem Body aus `.github/issue-bodies/` (erste Zeile `@softwarewerkstatt`). Die Zeitpläne greifen erst, sobald die Workflows den Default-Branch erreichen. Siehe die [Hilfe zur Review-Automatisierung](help/review-automatisierung.md).
- Apple-TV-App (tvOS) — Lean-back-Player via .NET for tvOS (`VideoPlayer.TvOS`, Issue #86): Eine neue eigenständige tvOS-App bringt die Medienbibliothek auf den Fernseher — vollständig per Siri Remote und tvOS-Focus-Engine bedienbar und auf demselben plattformneutralen MVU-Kern wie die Hauptanwendung gebaut. Die Serververbindung ist fernbedienungstauglich: automatische Servererkennung im lokalen Netz (mDNS + UDP), Liste bekannter Server inklusive Wechsel, manuelle Adresseingabe, Geräte-Kopplung per Einmal-Code oder Ticket-/Kurzcode, Anmeldung mit Benutzername/Passwort sowie automatische Wiederanmeldung aus dem Schlüsselbund. Die Startseite stapelt fokussierbare horizontale Karussells — Weiterschauen mit Fortschrittsbalken, Favoriten, Neu im Programm, die saisonalen Genre-Sektionen des Servers und eine Quellen-Reihe — mit Cache-First-Laden, Server-Ereignissen und Poster-Zwischenspeicherung. Das Quellen-Browsing bietet Suche, Genre-Filter und ein seitenweise nachladendes Poster-Raster; die Detailansichten decken alle Medientypen mit den Aktionen Abspielen, Herunterladen und Favorit ab. Die Wiedergabe läuft im nativen tvOS-Vollbildplayer mit Fortschritts-Tracking, Fortsetzungsposition, Auto-Fortsetzung (Serien- und Playlist-Kontext) und systemeigener Spurwahl. Playlists sind rein lesend verfügbar (gruppierte Übersicht, paginiertes Eintrags-Raster, Wiedergabe ab beliebigem Eintrag); manuelle Downloads laufen suspensionstauglich über eine `NSUrlSession`-Hintergrund-Session mit Ablaufdatum, Speicherkontingent, Abgleichslauf und einer Download-Seite mit Einzelaktionen; ein schlanker Einstellungsbereich deckt Aufbewahrungszeit/Kontingent, Auto-Fortsetzung und das „angesehen"-Endfenster sowie Konto-/Serverabschnitt ab. Auf tvOS nicht angeboten: Auto-Download-Vorlauf, „nach dem Abspielen löschen", Playlist-Verwaltung und Protokollversand. Zur Auslieferung gehören der App-Store-Asset-Katalog, ein signierter Release-Pfad (wiederverwendbare `package-tvos`-Action in beiden Merge-Workflows) und das Hilfsskript `scripts/tvOS-Deployment.ps1` für Mac-delegierte Builds — hinter `TVOS_SIGNING_ENABLED` geschaltet (siehe Wichtige Hinweise). Siehe die [tvOS-App-Hilfe](help/tv-app/index.md).
